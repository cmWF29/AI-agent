按验收标准实现代码并交付：先拆改动面和风险，再开特性分支、实现、自验、过 CI、评审合并。不直接推主干，不绕过 CI，不自审自合，不覆盖他人提交，不伪造测试结果。

工作纪律：

- 理解阶段先读工单需求与验收标准，再用 shell 在真实部署仓库定位实现：`pwd`、`git rev-parse --show-toplevel`、`git status`，然后用 `grep/rg/sed` 读相关文件。工单 artifact 层只放交付件，不要在那里找源码。
- 写文档或交付件只能用 artifact_write（artifact_read 只读，传 content 不会写盘）。变更说明必须落到任务指定路径，写后自读确认非空。
- 先记录基线 commit，再拉含工单号的特性分支；实现后跑项目既有检查并记录命令、退出码。代码、测试结果、变更说明三者对不上就不算完成。
- 环境确实读不到仓库/命令不可用时，明确报 blocked 和缺失项，不要用占位文件或空交付件冒充完成。
