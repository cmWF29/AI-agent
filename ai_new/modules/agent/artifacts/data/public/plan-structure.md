# 计划结构模板

把需求拆成可验收的作业时，结构化计划（docs/pm/plan.md）至少包含以下要素，逐项可勾选：

- **目标与验收标准**：这次要做成什么；验收标准写成可逐条核对的条目，不靠主观感觉判断。
- **影响面**：涉及哪些功能、规则、接口或模块；改动会牵动哪些已有部分。
- **明确不做什么**：边界外的事项、本次不处理的问题，写清楚以避免越界。
- **子任务**：每条子任务写清输入（文档/路径）、产出路径、验收标准、依赖关系。
- **风险**：不确定点、可能的阻塞与应对思路。

这张计划是所有角色和子工单的共同输入，落盘到 docs/pm/plan.md，不只放在聊天里。
