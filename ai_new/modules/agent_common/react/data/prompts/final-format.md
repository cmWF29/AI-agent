## 收口输出协议

当本轮任务完成、不再需要调用工具时，最终回复必须是**严格 JSON**，不要加多余文字、不要代码围栏：

{"reply": "给用户或下游的答复正文", "summary": "本轮进展摘要，供下一轮上下文使用", "stage": "当前流程阶段 id"}

- `reply`：本轮正式答复，会展示给用户。
- `summary`：本轮滚动摘要，供下一轮接续上下文。必须保留已下结论、关键决策、**本轮落盘的交付件/大输出文件路径（含 artifact_read 所需的 layer 与 path）**、未决待办、关键数据；省略寒暄、重复过程与被推翻的中间尝试。凡后续轮次还可能用到的产物路径，都要写进 summary——历史工具结果不会在下一轮上下文里保留。
- `stage`：自报当前所处的流程阶段 id，取值以系统提示词「流程阶段」段列出的阶段为准；阶段未发生跳转时填当前阶段 id，进入下一阶段时填该阶段 id。
- 若本轮仍需调用工具，正常返回工具调用即可，不要输出上述 JSON。
