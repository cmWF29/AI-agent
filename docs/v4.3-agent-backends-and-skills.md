# v4.3：Agent 循环后端插件 + 开源 Skill 管理

## 1. 结论先行

这次没有改业务分层，只把两处“变化点”做成插件：

1. **循环后端可插拔**：`api`（内核 ReactLoop）和 `claude-code`（已有 Agent CLI）都实现同一个
   `run(session, user_text, drain, hooks, max_steps)` 接口。Sessions 按会话记录里的 `backend`
   选择；工单/角色/交付件/结单/事件总线全部不变。
2. **Skill 是能力包，不是第二套角色库**：`library` 继续存角色、流程、技能三种记录；
   `skills` 模块只负责安装包、连接来源、解析 `SKILL.md`，再由“Skill 拆解者”把 Skill
   落成 `角色卡 + 技能卡 + 流程插件`。角色是“谁来做”，Skill 是“怎么做”，流程是“交什么、怎么验”。

## 2. 分层

| 层 | 负责 | 不负责 |
|---|---|---|
| kernel | `BackendRegistry` / `ApiLoopBackend`，ReactLoop、总线、HTTP、配置 | 业务角色、工单、Skill 语义 |
| agents 模块 | Claude Code 等已有 Agent 进程的适配器、`/api/agents/*` | 自己重写 ReAct、直接写工单存储 |
| sessions 模块 | 会话队列、并发、按 `backend` 选择循环、持久化 | 具体 CLI/API 实现 |
| library 模块 | 角色库/流程库/技能库；流程插件校验 | 下载/安装 Skill 包 |
| skills 模块 | 来源连接、安装包、解析 frontmatter、拆解入口 | 绕过 library 另存一套角色 |
| tickets 模块 | 工单生命周期、PM、角色、流程校验、结单 | 判断后端怎么跑 |
| web | 角色/流程/技能库、安装/拆解入口 | 直接改配置 |

### 2.1 后端接口

```python
class Backend:
    name: str
    def run(self, *, session, user_text=None, drain=None, hooks=None, max_steps=None) -> dict:
        # {"status": "ok", "final": "...", "steps": 1}
```

- `ApiLoopBackend`：只把 `ReactLoop.run(...)` 包一层，v4.1 行为不变。
- `ClaudeCodeBackend`：
  - 读取会话 `system_prompt`、最近对话、用户任务，写成 `data/agents/<session>/prompt-*.md`；
  - 以会话 `workspace` 为 cwd 启动 `claude -p ... --output-format json`；
  - 环境从统一 `llm` 配置推导：
    `ANTHROPIC_BASE_URL=<base_url>/anthropic`、`ANTHROPIC_AUTH_TOKEN=<api_key>`、
    `ANTHROPIC_MODEL=<model>`；
  - 解析 JSON 的 `result`，把结果写回会话消息，并通过 `hooks("llm.response", ...)` 进入时间线；
  - 非 `api` 后端跳过内核自动压缩（不拿外部 Agent 的上下文硬套 API 压缩）。
- 选择顺序：会话 `backend` → 流程插件 `flows[].backend` → `sessions.backend` 配置默认（`api`）。
- 新增后端：在 `Agents.setup` 里 `backends.register(...)`，Sessions 不需要改。

### 2.2 已验证

本机 Windows：

- Claude Code `2.1.319`（npm 全局安装）可用；
- DeepSeek Anthropic 兼容入口：`https://api.deepseek.com/anthropic`，模型 `deepseek-chat`；
- `claude -p "只回复两个字：正常" --output-format json --permission-mode bypassPermissions`
  返回 `result: "正常"`；
- 通过 `/api/agents/run` 和 `sessions.spawn(backend="claude-code")` 两次实测：
  外部 Agent 在会话 workspace 内创建 `hello.txt` / `session.txt`，内容分别为 `OK` / `SESSION`；
  会话记录 `backend=claude-code`，`sessions.wait` 能取回回复。
- 注意：Claude Code 会打印 `[claude-code:unrecognized_model]`，但请求和结果正常；这是 CLI
  对非 Anthropic 模型名的提示，不是本系统错误。

### 2.3 边界与未决

- 外部 Agent 目前拿到的是**本机文件/shell**，没有自动获得内核的 `ticket_*` / `library_*` 工具；
  它是“角色执行后端”，不替代 PM/秘书。需要内部工具时，下一步才是 MCP 桥，不在本次范围内。
- `toolpack.shell` 只限制 cwd，不是沙箱；外部 Agent 同样继承这个权限边界。
- CLI 未实现逐 token 流式；只发一轮 `llm.response` 完成事件，网页时间线仍可看到结果。
- `agents.claude_code.timeout` 默认 0（不设固定上限），靠会话插话 `abort` 结束进程；
  已实现 2 秒轮询 + `p.kill()`，但 Windows 子进程树尚未整体清理。

## 3. 开源 Skill

### 3.1 数据

- 包：`data/skills/packages/<id>/`，入口必须是 `SKILL.md`；`meta.json` 保存来源、frontmatter、资源清单。
- 技能库记录：仍写 `data/library/skills/<id>.json`，字段含 `package`、`source`、`assets`、`decomposed`。
- 角色/流程：拆解时走 `library.design`，生成 `roles/<role>.json` 与 `flows/<role>.json`。

### 3.2 来源

- `local`：本机目录，递归找唯一 `SKILL.md`。
- `github`：`https://github.com/<owner>/<repo>/tree/<branch>/<path>`，浅克隆后复制子目录。
- `raw`：`https://raw.githubusercontent.com/.../SKILL.md`，单文件安装（资源需另补）。
- 已内置来源：Anthropic `anthropics/skills`、MiniMax `MiniMax-AI/skills`、本地目录。
- `skill_sources` / `GET /api/skills/sources` 返回来源和示例；UI 可一键填入。

### 3.3 拆解

- 内置角色 `skill-decomposer`（Skill 拆解者）：读 `SKILL.md`，按“角色/技能/流程”三层拆；
- `skill_decompose` / `POST /api/skills/decompose` 的确定性结构拆解：
  - 角色 id：frontmatter `role` → 别名表（`pptx`/`ppt`/`slides` → `ppter`，
    `canvas-design` → `visual-designer`）→ skill id；
  - 必交产物：frontmatter `outputs` / `must_outputs`，否则按角色类型给默认（PPT/图片/文档）；
  - 角色提示词：Skill 正文 + 执行约束 + Skill 包绝对路径；
  - 流程插件：每个产物一条 glob 校验；
  - 角色卡补 `skill_id`、`skill_source`、`source=skill-decomposer`。
- 同一 Skill 重复拆解不会覆盖已有角色；要覆盖必须显式 `overwrite`。

### 3.5 许可证注意

Anthropic 的 `pptx` 等 document skills 在仓库中标注为 source-available / 非标准开源，
安装和自用可以，但**不要对外再分发或做衍生作品**；`canvas-design` 是 Apache-2.0 示例。
具体以每个 Skill 包内 `LICENSE.txt` 为准。
