# Hive Agent v4.2 自迭代记录

日期：2026-11-14。目标不是“再写新功能”，而是逐功能回答三个问题：是否符合预期、是否破坏架构、在架构的哪一层。随后补做审计遗留需求，并用真实网页逐项点击验收。

## 1. 结论先行

- 架构仍是 **kernel（内核）→ modules（业务模块）→ web（只读控制台）**，没有新增跨层调用。新增能力都落在既有模块边界内：空闲判断在 `idle`，工单标签在 `tickets` + `library`，文件浏览在 `projects` / `ops`，git 在 `gitflow`，交付件归档在 `artifacts`。
- 本轮修复了 6 类真实缺陷：路径穿越、结单硬门禁、sync 冲突漏登记、diff 归档错范围、压缩后不可读、队列失败静默丢失。
- 前端补齐了弹窗栈、深链关闭、Markdown 代码块、侧栏上下文、中文化、关闭态标签只读、模块“查看更早”、随机头像。
- 本地回归 `190/191`，唯一失败是 Windows 没有 `openssl`，HTTPS 实测被环境跳过；Linux VPS 回归会真正执行该项。

## 3. 逐功能代码审查：是否符合预期 / 是否破坏架构 / 在哪一层

### 3.1 内核层（kernel）

| 功能 | 结论 | 归属 |
|---|---|---|
| 配置 `load_config` | 通过；环境变量覆盖仍优先 | kernel/config |
| API 注册与调用 | 通过；模块只暴露 `ctx.api`，没有跨模块直接 import | kernel/api |
| 事件总线 | 通过；tickets 订阅 `session.result` 与 `gitflow.conflict`，没有反向依赖 | kernel/bus |
| HTTP 鉴权 | 本轮移除 `?token=` 查询参数鉴权，只接受 Header/Bearer/Cookie；`/api/health`、`/api/auth/*` 公开 | kernel/http |
| 存储 Collection | 新增 `valid_id()`；所有外部 ID 入口逐步校验 | kernel/store |
| trace 脱敏 | 回归通过：不落 api key / Bearer | kernel/trace |

### 3.2 业务模块层（modules）

| 模块 | 审查结论 | 关键边界 |
|---|---|---|
| `projects` | 项目名规范化去掉点号/斜杠，非法回退；项目文件浏览 `realpath + inside`；删除只清秘书会话，保留工单/知识/交付件 | 项目生命周期、项目文件树 |
| `tickets` | 工单状态机与角色编排；新增结单硬门禁、sync 失败阻断、diff 归档、标签只读、冲突订阅；`flow` 只展示实际发生节点 | 工单生命周期、角色 API、对外交付件 |
| `gitflow` | 工单分支/工作树/同步/合并；`ahead` 改为 `rev-list origin/main..HEAD`；merge 非冲突失败不再伪造 conflict；merge 串行锁；push 失败不算成功；changed 用 `origin/main...HEAD` 取工单自身改动 | git 基础设施，不掺业务语义 |
| `artifacts` | 三层归档；路径白名单；staging 原子替换；压缩后可列表/可读；只压缩已结单工单；归档串行锁 | 交付件存储与读取 |
| `library` | 角色/流程/技能/标签库；真 glob；contains 要求同一文件；内置角色保护（design 不允许覆盖）；flow_check 支持 root | 能力库与流程插件 |
| `idle` | 只判断与排队，不直接执行工单/消息；队列锁；失败保留并累计 attempts | 调度策略 |
| `sessions` | 会话生命周期、压缩、销毁归档；显式空 project 过滤 | 会话与上下文 |
| `webchat` | 群聊/模块时间线/直播/发送；closing 与 closed 都只读；live 按 ticket/project/global 精确过滤；模块早报可查询 | 展示适配层 |
| `toolpack` | 文件工具 realpath 限工作树；shell cwd 限工作树；shell 命令本身仍是已知权限边界 | 工具执行 |
| `health/ops` | 健康自检、交付件体积、源码只读、版本/回退 | 运维观测 |

### 3.3 控制台层（web）

控制台不直接写业务存储，只调用对外 API；页面状态全部由 `state.view/group/project/sideLayer/modalStack/navDepth` 驱动。

### 4.2 覆盖层与弹窗

| 组件 | 是否进历史 | 关闭优先级 |
|---|---|---|
| 交付件侧栏 `#side` | 否 | 弹窗 > 侧栏 > 抽屉 > 历史 > 页面层级 |

## 5. 本轮修复清单

1. 路径穿越：`valid_id` + projects/artifacts/gitflow/library 入口校验。
2. 结单硬门禁：缺必交产物 409，必须在 `closing` 前拦下；`_do_close` 再查一次，缺件退回 working，不销毁会话。
3. sync 冲突登记：订阅 `gitflow.conflict`，PM 过程中冲突也要求复验；closing/closed 消息与标签只读。
4. git 正确性：`ahead`、merge 非冲突失败、push 失败、changed 三点 diff、merge 串行锁。
5. 队列可靠性：锁、失败保留、`attempts/last_error`；只有 dispatch 成功才出队。
6. 压缩交付件可读：列表读 `<ticket>.index.json`，文件从 tar 的 `ticket/<rel>` 读取；只压缩已结单工单。
7. 归档原子性/按 diff：staging 后替换；changed 为空回退全量，避免空归档。
8. 库：真 glob、同文件 contains、内置角色保护、tag 项目路径校验、flow_check 内容校验需要 root。
9. 前端：弹窗栈、深链关闭、Markdown 代码块、侧栏上下文、健康/状态中文、按钮中文、401 停轮询、关闭态标签只读、模块“查看更早”、稳定卡通头像。

## 7. 未完成与已知边界

- 日历仍是 `idle.holidays` 配置列表，未接外部日历；判断逻辑已与日历解耦。
- 群聊仍是 900ms 轮询 + 5s 时间线，不是 SSE；功能可用，实时性不是最优。
- `/api/health/self` 继续公开给本机 watchdog 探活；不返回密钥。若要多用户部署，应加 localhost 限制或独立探活 token。
- `library.upsert` 仍可写入内置 id；`design` 已禁止覆盖内置角色。是否也禁止 upsert 覆盖内置，留待产品决定。
- `toolpack.shell` 只限制 cwd，不限制命令访问绝对路径；这是角色权限边界，不是沙箱。
- 压缩策略默认 7 天，保留 `index.json` 作为可见归档索引；是否删除 `index.json` 未定。
