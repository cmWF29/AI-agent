# v4.3 架构审查

日期：2026-11-14
范围：Web 控制台、Sessions、Tickets、Library、新增 Agents / Skills、测试与部署。

## 1. 可插拔循环后端

### 设计

`hive/kernel/backends.py` 定义 `BackendRegistry`，每个后端只暴露同一个
`run(session, user_text, drain, hooks, max_steps)`：

| 后端 | 位置 | 做什么 | 不做什么 |
|---|---|---|---|
| `api` | `ApiLoopBackend` | 包装 v4.1 的 `ReactLoop.run` | 不改变内核工具、消息、trace |
| `claude-code` | `hive/modules/agents.py` | 启动本机 Claude Code CLI，把 prompt/workspace 交给它 | 不自己写 ReAct；不自动获得内核 `ticket_*` / `library_*` 工具 |

`Sessions._run_task` 只做一次选择：

```
rec["backend"] -> BackendRegistry.get(...) -> backend.run(...)
```

所以“基于 API 的循环”和“基于已有 Agent 的循环”是同一个会话生命周期里的两个
流程实现；任务状态、插话、abort、交付件归档、结单门禁仍由 Sessions/Tickets 负责。

### 已验证

- `POST /api/agents/run` 用 `claude-code` 在临时 workspace 创建 `hello.txt`，内容 `OK`。
- `sessions.spawn(..., backend="claude-code")` 创建 `session.txt`，内容 `SESSION`，
  `sessions.wait` 返回 `ok`，会话记录保存 `backend=claude-code`。
- 外部 agent 默认 `timeout=0`，不设固定任务上限；每 2 秒轮询 `drain()`，
  收到 `abort` 后 `p.kill()`。实测长任务在 2.1 秒被中断，返回 `backend_aborted`。
- Claude Code 的 npm 全局安装位置由 `_resolve_command()` 自动查找
  （`%APPDATA%\npm\claude.exe` 等），服务进程 PATH 不含 npm 时也能启动。

### 边界

- 外部 Agent 目前直接使用会话 workspace 的文件/shell，不是内核工具沙箱；
  这是有意的“角色执行后端”边界，PM/秘书仍走 API。
- 需要外部 Agent 调内核 `ticket_*` / `knowledge_*` 时，下一步是 MCP 桥；
  当前未实现，文档和代码都没有把它说成已完成。
- Windows 子进程树未整体清理；`p.kill()` 只杀主进程。Linux 上可通过进程组补强。
- CLI 没有逐 token 流式；时间线在完成后收到 `llm.response` 事件。

## 2. Skill 管理与拆解

### 数据模型

- 包：`data/skills/packages/<id>/`，入口 `SKILL.md`，`meta.json` 记来源/frontmatter/资源。
- 角色/流程仍写 `library.skills`，不另造一套角色库；`library` 是唯一元数据源。
- 内置来源：
  - `anthropics/skills`
  - `MiniMax-AI/skills`
  - `obra/superpowers`
  - 本地目录
- 安装来源支持 GitHub tree、raw `SKILL.md`、本地目录；GitHub 路径校验拒绝
  `..`/绝对路径，clone 临时目录在复制后清理。

### 拆解

`skill-decomposer` 角色读 `SKILL.md`，产出：

- 角色：谁做；`role` 从 frontmatter 别名表或 skill id 推断（`pptx` -> `ppter`，
  `canvas-design` -> `visual-designer`）。
- 必交产物：frontmatter `outputs` / `must_outputs`，否则按类型默认
  （PPT `**/*.pptx`、图片 `**/*.png` 等、文档 `docs/**/*.md`）。
- 流程插件：每个产物一条 glob 校验。
- 角色提示词 = Skill 正文 + 执行约束 + Skill 包绝对路径。
- 重复拆解不覆盖已有角色；显式 overwrite 才覆盖。

### 已验证

- `canvas-design` -> `visual-designer`，生成 `poster.png`（512×512，242,880 B）
  和 `design.md`（4,961 B）。
- `pptx` -> `ppter`，用 pptxgenjs 生成 `demo.pptx`（91,944 B，3 页）。
- `pptx-generator` 也映射 `ppter`，第二次拆解不覆盖已有角色。
- 生产 VPS 通过 UI 安装并拆解了上述三个 Skill；角色卡可见 `ppter`、
  `visual-designer`，流程卡有 `**/*.pptx` / 图片 glob 校验。

### 许可证

Anthropic 的 document skills（含 `pptx`）是 source-available / 非标准开源；
不要对外再分发或做衍生作品。`canvas-design` 是 Apache-2.0 示例，
具体以包内 `LICENSE.txt` 为准。`meta.json` 保留 `license`，UI 详情可查。

## 3. 前端路由与弹窗

本轮真机验收发现并修复：

1. 地址栏直接改 hash 时旧弹窗盖在新路由上 → 增加 `hashchange` -> `applyRoute`。
2. 项目/源码文件详情关闭后回到根目录 → `openProjectFiles(path)` /
   `openSource({path})` 单次请求当前目录，避免根目录请求与目录请求竞态。
3. 项目页点“群聊”顶部标签无反应 → 项目视图下 `selectGroup` 回到上次会话。
4. `pv-files` 直接绑定函数导致 MouseEvent 被当作 path → 包一层无参函数。
5. 拆解角色显示名用 frontmatter name（pptx） → 改用 role id（ppter）。
