# 技术方案原理

本文说明系统为什么这样设计，不复制实现细节。代码只在定位问题时出现，指向模块或符号，不列函数体、不贴 diff。实现层面的字段、状态表、并发顺序与失败处理见《技术细节》。

## 1. 目标与边界

系统要同时满足四件事：多项目/多工单互不越界、多个节点能安全协作、资料能增量同步到远端、前端和核心机制可被门禁持续看护。

非目标：不把系统做成通用云平台，不在本轮解决跨主机强一致数据库、不限流量的对象存储网关、也不承诺 Windows 强隔离已经与 Linux 等价。边界必须显式，不能拿“看起来能用”冒充“商用完成”。

## 2. 中央编排、模块分离、纯函数

设计采用“中央编排 + 能力模块 + 纯计算下沉”的结构：

- 编排层只负责按需求顺序调用能力，决定状态迁移与落盘时机；
- 能力模块拥有自己的数据与路由，不互相 import 私有实现；
- 纯函数只做数据成形、判定与差分，不读盘、不取时钟、不发网络请求；
- 有副作用的动作统一收口成效果清单，由运行时落盘或派发。

这样做的原因是可测试性和故障定位：状态机、差分、压缩、租约判定都能在无环境依赖下被用例打穿；写盘、网络、进程这些不可控部分集中在少数边界，失败时能定位到“算错了”还是“落盘错了”。

## 3. 隔离模型

隔离不是路径字符串判断，而是执行时的文件系统视图。

每次 shell 执行启动独立的 mount namespace，只把当前工作负载需要的目录 bind 进去：工单会话看到本工单目录、公共文档、日志和交付件；项目根不整体挂载；宿主 `/home` 不可见。namespace 内的工作目录固定在工单视图，进程退出 namespace 即销毁。namespace 内的 cwd 与 bind 目的地先按 POSIX 语义归一化，任何 `..` 片段在进入 bwrap 参数前就被拒绝；不能只用“字符串以 /workspace 开头”判断包含关系。

关键取舍：没有在宿主上给每个项目常驻 mount 根。常驻 mount 会带来跨进程泄漏、卸载竞态和高权限维护问题；按 workload 起 namespace 更接近多租户执行器的通用做法。代价是每次执行有 namespace 启动成本，且依赖宿主具备 bubblewrap 与相应内核能力。

边界：mount namespace 只解决“看得到什么”，不解决资源限额、系统调用过滤和网络隔离。当前没有 seccomp、cgroup 和独立网络命名空间；这些是下一层能力，不能因为目录隔离通过就认为执行环境已经完整。

## 4. 分布式协调

协调台账不使用进程内全局字典。每次读写都从持久化台账读取，更新走“读取 → 深拷贝 → 回收过期租约 → 纯函数变更 → 原子比较交换提交”的循环；比较交换失败就重读重算，超过重试上限显式返回冲突耗尽，不静默覆盖。

租约带过期时间与 fencing epoch。节点仍存活但租约过期时也按失效处理；新持有者接手时 epoch 递增，旧持有者的写请求带旧 epoch 会被拒绝。这样避免“心跳还在、租约已经过期”造成的双写。

原子比较交换依赖同机文件锁。单机内可以保证并发安全；跨 VPS 共享同一台账需要共享文件系统或远端协调服务，当前没有把本地文件锁伪装成跨主机锁。跨主机部署必须显式配置共享存储，否则只能做到节点各自独立台账。

登录失败节流复用同一套 CAS 台账，但它是“防护状态”不是“业务租约”：按 `ip:<peer>` 与 `pair:<peer>|<user>` 计数，窗口内失败达到阈值后写入锁定期；成功登录只清除自己的键。刻意不按账号单独锁，否则任意攻击者可以用任意用户名把管理员锁死，形成定向 DoS。锁定期内先拒绝、不再做摘要比对，避免把 CPU 开销与账号是否存在变成侧信道。台账写不进去时 fail-closed 返回 503，不静默放行。

## 5. 云端存储

云端同步以远端 manifest 为权威提交点，而不是把本机缓存当真相。

同步分三步：先读远端 manifest，和本地清单、上次推送清单做三方差分；再上传新增或变更对象；所有对象成功后写 manifest。manifest 写失败不报成功、不更新本机已同步缓存，下一轮只补 manifest。远端对象被外部修改时，计划阶段报冲突，不静默覆盖。

删除采用显式 prune：本地删除只形成待删清单，默认返回“需要 prune”并阻止 manifest 更新；只有调用方明确要求删除传播时才删远端对象。原因是远端可能是多台机器共享的资料库，自动删除会把别人仍在用的对象变成孤儿。

当前边界：没有对象存储条件写（If-Match/If-None-Match）级别的写时并发保护；冲突检测发生在计划阶段，计划到上传之间仍有竞态。对象存储的强并发语义要等 provider 层补齐条件写后再谈完整。

## 6. 流程状态机与清单状态机

流程状态机是显式契约，不是散落在提示词里的阶段名。契约包含状态、邻接边、终态、每个状态的交付件检查和 must/forbid 清单；活跃集合支持并行分支，离开的当前态从活跃集合摘除，兄弟分支保留，目标态并入。

一次迁移必须同时满足：目标存在、边从某个活跃态可达、源状态的 must 项已交齐、没有踩 forbid、源状态声明的交付件已落盘。任一不满足就拒绝迁移并保留原活跃集合。拒绝原因是结构化的，前端能显示“缺哪一项、踩了哪条”，而不是只报一句失败。

清单状态机与会话待办是同一套数据：条目有稳定 id、三态 status、文本与备注；增删改查是纯变换，只有真实字段变化才产生会话补丁。清单上限是硬约束，配置缺失/为 0 时必须保持空表；查询、只带 id 的空 update、内容相同的 replace 都不能写回一份“看起来变了”的补丁。清单上下文挂在 system 消息上，因为逐轮压缩只保留 system、滚动摘要和最后一条用户指令，挂在普通消息上的清单会被压掉。

## 7. 逐轮压缩

会话存档保留全量消息供回溯，但发往模型的上文不是全量历史。发模型时只带 system、滚动摘要和最后一条用户指令；本轮 ReAct 新增的 assistant/tool 往返追加在同一视图内。收口后，模型给的摘要优先；模型没给摘要时，系统按显式字符上限把本轮工具往返压成兜底摘要，并标明是系统兜底。

压缩上限是对整段滚动摘要的硬约束，不是只截本轮新增正文。旧摘要和本轮兜底拼完仍超限时必须整段截断，否则配置的预算会被旧摘要吃掉。压缩失败或模型未交摘要时保留旧摘要，不允许清空历史。

## 8. 前端：数据驱动与信息预算

控制台是原生 HTML/CSS/JS，无构建步骤。页面由视图规格驱动：菜单、区块、卡片、表格、表单、动作、状态机声明都在数据里，渲染层只认原语，不持有业务字面量。新增页面或按钮不登记规格，门禁直接红。

控件级状态机分两层：页面级 click machine 管“这一下能不能点”，控件自身用 idle/busy/done/disabled 表示当前按钮状态。每个可点实例必须同时有控件 id、点击种类、去向和状态机；只写 `data-act` 不写 `data-ctl` 的一律算漏登记。

信息预算的原则是“主界面只放决策信息，解释收进详情”。网格卡最多两行 meta，路径、创建时间、最近活动等细节进项目详情；区块说明不超过一行；长帮助、示例、原理放说明按钮、浮窗或抽屉。品牌区不用渐变、发光和装饰阴影。这样不是删功能，而是把同一个功能分层：主界面扫状态，详情页查上下文。

## 9. 门禁体系

质量不靠人记得跑，而靠分层门禁：

- 静态层防结构退化：控件状态机、界面状态图、可点实例、视图条件、卡片尺寸、文案、接线、代码文档同步；
- 单元层防逻辑退化：纯函数、状态迁移、并发、幂等、边界；
- 契约层防不可信输入打穿：鉴权、越权、路径穿越、非法参数、重复投递；
- 输入形状层防“合法路由 + 坏形状”打穿：摘要算法、随机串长度、十六进制截断、WAV/JSON/SSE 解码、LLM 报文、工单标题/正文/子单列表都在进入业务前收口，坏形状返回结构化错误码而不是抛异常；
- 系统层防接线断裂：真浏览器 + 真后端跑项目/工单闭环，逐页巡检，逐控件真实点击；
- 入口层防“带凭据的链接变成写操作”：GET 只放行显式读入口，匿名面是 allowlist，请求体先量长度再读，分块传输直接拒绝；令牌放 query 只对 SSE 开，其它 API 一律当未登录，避免令牌进日志和 Referer；
- 韧性层防“进程死了状态还在跑”：真实子进程 SIGKILL、6 进程抢同一键、租约过期 sweep、恢复后不双跑；
- 覆盖率门禁防“测试写了但没覆盖”：行覆盖、分支覆盖和关键机制模块分别设下限；
- 改动行门禁防“老代码高分掩盖新代码裸奔”：本轮新增/修改的产品代码行必须 ≥90% 被执行；
- 韧性层防中断恢复：进程被杀、租约过期、重复投递、恢复后不双跑。

门禁必须能真失败：每条规则要么有反例自测，要么有真实 DOM/真实落盘证据。只检查文件存在、只断言 HTTP 200、只截图不看状态，都不算门禁。

## 10. 取舍与已知风险

- 单机文件 CAS 换来了零外部依赖，但跨主机需要共享存储；不把单机保证外推。
- manifest 最后提交换来了可恢复，但计划到上传之间仍有竞态；条件写是下一层。
- bwrap 每次执行换来了低泄漏，但没有资源限额和系统调用过滤；高负载多租户还需 cgroup/seccomp。
- 前端信息预算换来了清爽，但详情入口必须可达；门禁同时检查入口、关闭路径和真实点击，不允许“精简到找不到”。
- 覆盖率 100% 是唯一门槛，不是“最好达到”的目标值；关键机制模块单独设线，避免整体数字掩盖核心裸奔。平台互斥分支走 Linux + Windows 合并口径，不靠单端排除模块或 `pragma` 凑数。
- HTTP 入口单独收口，不把“浏览器带 Cookie”当成授权：GET 只用于读入口，写路由一律 POST；匿名路径是固定 allowlist，新增 auth 路由不会因为前缀相同自动公开；请求体超过上限直接 413，chunked 直接拒绝，避免未消费字节污染下一条请求。
- 鉴权与执行边界一律 fail-closed：空摘要、缺失过期时间、非法会话令牌、越界虚拟路径都拒绝，不把“下游可能拦住”当成安全边界。
- 改密也按 fail-closed：期望摘要为空表示账号尚未建立可用凭据，旧摘要空或与期望不一致一律拒绝，不能把“没有旧密码”当“旧密码正确”。
- 前端片面的匿名资源白名单同样危险：只有 css/js/图片/字体等无数据壳资源可匿名取，json/yaml/md 按页面处理，必须登录。
- 登录失败节流已经落地：持久化 CAS 台账、按 IP/组合键计数、锁定期内拒绝正确口令；不按账号全局锁，避免定向 DoS。它仍是单机文件台账，跨 VPS 共享同一防护状态需要共享文件系统或远端协调服务；没有做验证码、设备指纹和长期审计归档，在线撞库防护仍是分层能力而不是单一开关。
