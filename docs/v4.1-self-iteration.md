时间：2026-11-14 凌晨。目标：在 v4 已上线的基础上，做需求复盘、架构审查、缺陷修复、前端返回/状态机、真实测试与部署，不新增超范围功能。

## 1. 本轮做了什么

### 前端：返回键 + 刷新恢复 + 状态机

- 新增 hash 路由：
  - `#/chat/secretary`、`#/chat/sec-<p>`、`#/chat/<T-id>`
  - `#/project/<p>`
  - `#/library/<roles|flows|skills>`、`#/health`、`#/versions`、`#/source`
- 新增顶栏 `←` 返回按钮，PC 与安卓一致；Esc 同样生效。
- 新增 `popstate`：安卓物理返回、浏览器返回都按 hash 恢复页面，不会重复 push。
- 刷新不再回到根页面；分享链接可直接定位项目/工单。
- 返回优先级：弹窗 → 交付件侧栏 → 移动端抽屉 → 历史栈 → 层级回退（工单→项目→根）。
- PC 侧栏收起状态写入 `localStorage`，刷新后保持。
- 完整状态转移图见 `docs/ui-state-machine.md`（Mermaid + 转移表 + 验收清单）。

### 缺陷修复

1. **路径越界前缀绕过**：`startswith(base)` 会被 `/a/bc` 绕过；统一改为 `inside(base,target)`（realpath + 分隔符）。覆盖项目文件、源码浏览、静态页。
2. **工单群发言人错位**：用户本人在工单群说的话之前被渲染成“秘书→PM”的派活。现在：
   - 用户发言显示“我”；
   - PM kickoff 仍是“秘书→项目经理”；
   - PM 派活显示“项目经理→角色”；
   - `（系统）` 开头的续跑/催补/冲突提示不进入群聊。
3. **系统消息混群聊**：流程催补消息加 `（系统）` 前缀并在群聊过滤。
4. **流程插件可被空文件骗过**：校验项新增 `min_bytes` 与 `contains`；空文件/占位文件不再算“架构文档已交付”。
5. **冲突后复验只是口头提醒**：新增 `ticket_verify` 工具与 `POST /api/tickets/{id}/verify`；冲突工单写 `reverify.required`，未登记复验时 `ticket_close` 返回 409，不能结单。
6. **删除工单残留分支**：新增 `gitflow.ticket_remove`，删除工单时清工作树 + 临时分支；交付件/知识保留。
7. **trace 可能落密钥**：对 `api_key`/`authorization`/`token`/`secret`/`password`/`cookie` 字段与 `sk-*`/`Bearer *`/`token=*` 值脱敏，落盘前替换为 `[redacted]`。
8. **Collection 并发写**：给 `Collection.put/delete/list` 加可重入锁，避免 HTTP 线程、空闲线程、工单线程同时写同一 JSON 时丢更新。
9. **安全响应头**：静态页与 API 增加 CSP、`X-Frame-Options: DENY`、`nosniff`、`Referrer-Policy`；HTTPS 加 HSTS。
10. **登录暴力破解**：同 IP 5 分钟 5 次失败后返回 429；HTTPS 下 Cookie 加 `Secure`。
